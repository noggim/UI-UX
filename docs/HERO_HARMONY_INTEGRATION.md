# 용사와 맵 조화 — 게임 적용 (2026-10-27)

> **H2 후속 적용 완료:** 앞뒤·대각선 걷기, 새 검 8종, 손 추적, 걷기 잔상 제거와 용사 명암 보정을 게임에 연결했다. [현재 적용 기록](HERO_SWORD_RUNTIME.md)과 [자산 계약](HERO_SWORD_WALK_ASSETS.md)을 따른다. 아래 PNG 규격과 129개 테스트는 최초 harmony 적용 당시 기록이다.

작은 머리·길어진 몸통과 다리·위에서 내려다보는 시점의 용사를 게임에 연결했다. 회백색 머리, 진홍색 목도리, 남색 옷, 갈색 장비를 유지한다. 걷기·구르기는 앞/뒤/옆/앞 대각선/뒤 대각선 5개 원본 방향을 사용하며 왼쪽은 좌우 반전한다.

작업 브랜치는 **`haeseong/game`**이다. 중간발표용 **`middle-term`은 `d4444d2`로 유지**한다. `main` 병합은 별도다. 새 `design/` 자료와 검수 캡처는 사용자 결정에 따라 커밋하지 않는다.

이미지는 built-in ImageGen으로 만들었다. 생성 원본 바이트를 그대로 복사했으며 오프라인 리사이즈·재양자화·재인코딩은 하지 않았다. `hero-motion.json`에 각 PNG의 SHA-256을 기록했다. 실제 생성 크기와 간격이 요청한 256×288 고정 칸과 달라 **예전 `walk.png` / `roll.png`에 덮어쓰지 않았다.** 기존 파일은 비교/호환용으로 보존한다.

`HeroAtlasData`는 원본 영역과 발 기준을 검증하고 `HeroMotionAtlas`가 원본 텍스처를 읽는다. `HeroPose`와 `ActorInk`는 같은 가상 캔버스(64×72, 발 중심 x32/y68)에 각 자세를 **가로·세로 동일한 비율**로 그린다. 원본 파일을 고치지 않고 표시할 영역만 선택한다. 잘못된 좌표·크기는 조용히 자르지 않고 오류로 처리한다.

서기는 **세 번째 프레임(index 2)**이다. 요청서의 첫 번째 프레임 설명보다 현재 게임 계약을 따랐다. 걷기는 인접 자세를 부드럽게 연결하고 정지할 때 서기 자세로 돌아온다. 구르기·잔상·피격 색에도 같은 좌표 변환을 적용한다. 위쪽 대각선에서는 검을 몸 뒤에 그린다.

## 클로드 변경과 연결

- `hero/8-direction`의 `abc086ea3dc3280b96a0c74f5cf53541144c72e0`만 `cherry-pick -x`로 가져왔다. 이 브랜치에서는 `cb8df66`이며 원래 저자와 출처를 보존한다.
- 기존 `HeroMotion.row()`는 오래된 3행 그림의 대체 표시용으로 유지한다. 새 그림은 `HeroAtlasData.row()`의 5방향 행을 사용한다.
- `claude/project-thread-vzxje2`의 `6c20eef`에 있던 `docs/GPT_HERO_HARMONY.md`를 참고했다. 그 브랜치의 지도/이동 경계 변경과 `map/replenishment`는 이번 적용에 포함하지 않는다.
- 생성 방향: 작은 머리의 3.5~4등신을 목표로, 약 40° 내려다보는 시점, 회백색/푸른 회색 머리 명암, 진홍색 목도리, 짙은 남색과 갈색 가죽, 따뜻한 빛과 차가운 그림자, 빈손·투명 배경·별도 그림자 없음. 반대 발 접지 자세는 추가 생성했다.

## 표시 크기와 게임 규칙

현재 몸 높이 약 58월드px와 64×72 표시 영역을 기준으로 맞췄다. 원본 자세에 따른 높이 차이는 자연스러운 보폭/웅크리기로 남긴다. 1.3배 확대, 잡몹 일괄 확대, 추가 주변광/그림자 조정(C1~C4)은 이번에 적용하지 않았다. 기존 조명·윤곽 처리에 새 그림을 연결한 범위다.

충돌 크기, 이동 속도, 구르기 거리/시간, 공격 판정, 카메라, 방 그림과 통로는 변경하지 않았다. 검은 기존 장착 무기 시스템에서 별도로 그린다. 대장간 작업·수면·HUD 초상은 각각의 기존 전용 자산을 유지한다.

## 검증과 재현

- Java 17: `:core:test :lwjgl3:dist` 성공. **129개 테스트, 실패 0 / 오류 0**.
- 새 테스트는 원본 해시/실제 PNG 크기, 모든 프레임의 투명 여백과 가시 픽셀 잘림, 발 기준의 동일성, 가로·세로 배율 일치, 대각선 행, 잘못된 데이터 거부를 확인한다. PNG 변경도 테스트 입력에 포함한다.
- 같은 빌드에서 `-Dyongsa.heroArt=legacy`로 실행하면 이전 3행 그림으로 비교할 수 있다. 기본 실행은 새 그림을 사용한다. 이 옵션은 개발 비교용이며 저장 파일에 기록되지 않는다.
- 실제 Java/LWJGL에서 CAMP/L3/R1/T3, 각 방향, 대각선 구르기 시작/회전/회복, 피격 색, 몬스터 옆 외형과 걷기·구르기 각 30개 자세를 캡처했다. 카메라는 일반 설정 115%와 동일하다. 동일 위치의 이전 그림도 별도 실행으로 비교했다.
- 기존 시각 검수도 정상 종료했다. 타이틀·HUD·가방·대장간·보스·작은 창 등 22개 캡처를 생성했고, 강화 결과 5종의 1회 처리 및 키 입력 보호 검증을 통과했다.
- 검수 도구/캡처는 로컬 `design/hero-harmony-h-2026-10-26/`에 보관한다. 원본 측정 좌표는 이번 런타임 JSON이 기준이며 이전 브라우저 시안의 `review.json`을 게임 규약으로 쓰지 않는다.

실행: `haeseong/game`을 가져온 뒤 `./gradlew.bat lwjgl3:run`, 또는 `./gradlew.bat lwjgl3:dist` 후 `lwjgl3/build/libs/yongsa-game-0.1.0.jar`를 실행한다. 팀원에게는 `design/` 없이 코드·`assets/`만 있으면 새 용사가 표시된다.
