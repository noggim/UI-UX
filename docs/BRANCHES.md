김선우의 이전 작업은 이미 팀 통합 이력에 포함되어 있다. 현재 별도 원격 브랜치가 없으므로 임의로 만들거나 담당자를 재지정하지 않는다. 표의 담당자는 브랜치를 관리하는 사람이며, 그 브랜치의 모든 코드·그림을 혼자 만들었다는 뜻은 아니다. 원래 커밋과 저자 이력은 유지한다.

## 앞으로 작업할 때

1. 현재 폴더와 브랜치, 미커밋 변경, GitHub 최신 상태를 확인한다. 다른 사람이 사용하는 폴더의 브랜치를 임의로 전환하지 않는다.
2. `haeseong/game`의 기존 변경을 포함한 상태에서 작업한다. 별도 작업 폴더가 필요해도 기능별 원격 브랜치를 만들지 않는다.
3. 코드·게임에 적용하는 `assets/`의 그림·필요한 적용 문서를 커밋하고 `haeseong/game`으로 올린다. 아래 디자인 자료 제외 규칙을 지킨다. 열려 있는 누적 PR을 갱신한다. 그 PR이 병합/종료된 경우에도 동일 브랜치를 계속 쓰며, 새 PR이 필요하면 현재 누적 범위로 작성한다.
4. 작업별 검증을 마치고, 그림 시안만 저장한 것과 게임에 적용한 것을 구분해 기록한다.
5. 팀원 브랜치와 `main`은 별도 요청이나 합의된 병합 절차 없이 삭제·덮어쓰기하지 않는다.

### 디자인 작업 자료 업로드 — 2026-10-23 사용자 결정

다음 업로드부터 `design/`의 새 자료와 기존 자료의 수정분은 올리지 않는다. `.gitignore`의 `/design/` 규칙은 새 파일을 기본 커밋 대상에서 제외한다. 이미 추적 중인 파일에는 적용되지 않으므로 파일을 명시해서 스테이징하고, 커밋 전에 `git diff --cached --name-only -- design/`의 출력이 없는지 확인한다. `design/`에 강제 추가를 사용하지 않는다.

기존 GitHub 디자인 자료와 로컬 원본은 보존한다. 과거 파일의 삭제·추적 해제·이력 재작성은 이번 결정에 포함되지 않는다. 게임에 실제 적용되는 그림과 데이터는 `assets/`, 팀이 필요한 설명은 `docs/`에 계속 올린다. 기존 테스트가 읽는 디자인 점검 자료도 현재 추적 상태를 유지한다.

```powershell

```
