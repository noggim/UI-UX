# H3 걷기 재작업과 실제 적용 — 2026-10-28

`GPT_HERO_WALK_CYCLE.md`의 W1을 게임에 적용했다. 앞·뒤·옆·앞 대각선·뒤 대각선의 걷기 20자세를 다시 만들고, 모든 행을 `[0, 1, 3, 4]` 순서로 재생한다. 0/3은 반대쪽 발의 착지, 1/4는 발이 옆을 지나가는 자세다. 예전 임시 순서에서 같은 자세를 반복하던 부분을 교체했다.

## 자산과 연결

- `assets/sprites/hero-motion/harmony/walk.png`: 앞·뒤 두 행.
- `walk-side.png`: 옆 한 행. 옆걷기는 이제 이 그림만 사용한다.
- `walk-diag.png`: 앞·뒤 대각선 두 행. 왼쪽 방향은 기존 반전 규칙을 따른다.
- 각 행의 2번 서기는 이전 그림의 RGBA 픽셀을 그대로 옮겼다. 크기·발·손의 상대 좌표와 표시 배율도 보존했다. 5번은 사용하지 않으며 1번을 복사해 둔다.
- `hero-motion.json`의 프레임 영역·발·오른손·축척·원본 크기와 해시를 갱신했다. 새 그림의 표시 높이는 착지 약 58월드px, 지나가기 약 58.25월드px다. 원본 PNG의 가로/세로 늘리기나 색 재양자화는 하지 않았다.
- 한 방향의 걷기 네 자세는 같은 생성 시트에서 가져온다. 이전 `stride` 그림은 걷기와 로딩 목록에서 제외했으며 파일 자체는 보존했다.
- 검을 아래로 내려 드는 Claude의 각도 수정과 손 추적을 유지했다. 구르기·검 원본과 게임 이동 속도도 바꾸지 않았다.

## 함께 보정한 부분

새 자세 자체에 발을 넘기는 움직임이 있는데, 렌더러가 몸을 추가로 최대 1.3월드px 띄우면 지지하는 발까지 올라가 보였다. 새 용사에서는 추가 상승을 최대 0.2월드px로 줄였다. 예전 용사를 비교하는 `legacy` 모드의 값은 유지한다. 걷기 시간은 기존처럼 실제 이동 거리에 비례하므로 벽에 막히거나 느려지면 발도 그에 맞춰 움직인다.

## 확인

Java17 `:core:test` **141개 통과, 실패/오류 0**, `:lwjgl3:dist` 성공.

변경 전후 캡처 각 512장 생성을 확인했다. 캠프의 8방향 실제 이동 프레임 240장과 CAMP/L3/R1/T3의 자세 비교 화면에서 발 교대, 크기, 검의 손 연결을 검수했다.

- 기존 서기 다섯 자세의 RGBA 해시가 이전과 일치하는지 확인한다.
- 걷기에 서기 프레임이 끼지 않는지, 각 방향의 네 하체 그림이 서로 다른지, 같은 시트를 쓰는지, 표시 높이와 발·손 좌표가 유효한지 검사한다.
- 원본 PNG 크기·해시·잘림·손 좌표·좌우 반전·공격 변형 검증과 던전 이동/전투/저장 등 전체 테스트를 함께 실행한다.

`HeroEquipmentLauncher`는 실제 렌더러를 사용한다. CAMP/L3/R1/T3 × 8방향 × 8동작 256장, 검 8종 × 두 방향 16장, 실제 캠프 이동 입력 8방향 × 30프레임 240장으로 실행당 총 512장이다. 캠프에서 시설과 충돌하지 않는 구간을 찾아 실제 `GameSession.update`로 이동하며 매 프레임 이동 거리와 GL 오류를 확인한다. 고정 동작 검수와 자동 이동 검증이며 전체 수동 플레이를 뜻하지 않는다.

```powershell
.\gradlew.bat :core:test :lwjgl3:dist
java -cp lwjgl3/build/libs/yongsa-game-0.1.0.jar com.yongsa.lwjgl3.HeroEquipmentLauncher build/h3-after-captures
```

변경 전후 캡처는 로컬 `build/h3-before-captures/`, `build/h3-after-captures/`에, 비교 화면·GIF와 원본은 `design/hero-walk-h3/`에 보관한다. 신규 검수/디자인 자료를 Git에 올리지 않는 기존 사용자 결정을 따른다.

생성은 내장 `image_gen`으로 진행했다. 같은 발 반복, 가려진 오른손, 지나가기 자세의 크기 차이는 후속 생성으로 교정했다. [프롬프트·선택 원본·해시·좌표 기록](hero-walk-h3-generation.json)에 재현 정보를 남겼다. 게임 파일에는 선택한 그림의 픽셀을 손실 없이 분리·배치했고, 서기 자세의 기존 픽셀을 함께 보존했다.
